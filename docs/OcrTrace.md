# OCR トレースの記録と再生

OCR 追跡の不具合を再現するための開発者向け機能です。通常は無効です。OCR 文字列には個人情報や機密情報が含まれることがあるため、必要なときだけ明示的に有効にしてください。

## 記録を有効にする

WindowTranslator の起動引数に `--OcrTrace:Enabled=true` を指定します。保存先を変える場合は `--OcrTrace:Directory=C:\trace-output` も指定します。設定ファイルを使う場合は `appsettings.json` のルートに `"OcrTrace": { "Enabled": true, "Directory": "C:\\trace-output" }` を追加できます。記録が始まるとログに実際のファイルパスが表示されます。

保存先を指定しなければ、通常版は `%USERPROFILE%\.wt\ocr-traces`、Debug ビルドは `%USERPROFILE%\.wt.debug\ocr-traces` に保存します。翻訳対象のウィンドウごとに `ocr-*.jsonl` ファイルが作られ、1 行に 1 フレームを追記します。ファイルは記録中も読み取り可能です。記録を止めるには起動引数を外して再起動してください。古いトレースは自動削除されません。

各行には形式バージョン、フレーム番号、記録開始からの相対時刻（`RelativeTimeTicks`）、画像の幅と高さ、`IOcrModule.RecognizeAsync` が返した統合済みの OCR 文字列と矩形情報（X、Y、Width、Height、FontSize、Angle、MultiLine）が入ります。画像、翻訳結果、色は保存しません。書き込みは別スレッドで行い、記録に失敗しても OCR と翻訳は継続します。書き込みが追い付かない場合はキューを超えたフレームを省略し、その件数をログに記録します。

## 再生と評価

`OcrTraceReplay.ReplayAsync(stream, tracker)` に JSON Lines ファイルの `Stream` と新しい `OcrTextTracker` を渡します。返される `OcrTraceReplayResult` は、元のフレーム、そのフレームの安定化済み `TextRect`、追跡処理時間を含みます。再生器はフレーム順序、画像サイズ、相対時刻を使って追跡処理を呼び出し、画像サイズの変更時にはトラッカーをリセットします。アルゴリズム変更前後の比較には、同じトレースをそれぞれ新しいトラッカーへ再生してください。使用例は `WindowTranslator.Tests/OcrTraceTests.cs` を参照してください。

トレースと再生結果から位置・サイズ変動、文字列変更、欠落復帰、変更反映の遅延、処理時間を集計できます。論理トラック ID や分割・統合の内部状態は現在の出力に含まれないため、それらの指標には追跡器側の診断情報が別途必要です。

`Version` が 1 のファイルを読み込みます。未知の追加フィールドは無視し、未対応バージョンは明示的なエラーにします。フレーム順序・相対時刻・画像サイズの不正値もエラーになります。

## 共有前の確認

不具合報告に添付する前に、JSON Lines の全文を開いて OCR 文字列を確認してください。機密情報があれば共有用のコピーから削除または置換してください。対象画像は保存されませんが、認識された文字列はそのまま残ります。
