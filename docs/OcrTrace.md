# OCR トレースの記録とテスト

OCR 追跡の不具合を再現するための開発者向け機能です。OCR 文字列には個人情報や機密情報が含まれることがあります。

## 記録方法

DEBUG ビルドで翻訳対象のウィンドウをアタッチし、タスクトレイの「アタッチ中」から対象ウィンドウの「OCRトレース記録を開始」を選びます。同じメニューの「OCRトレース記録を停止」で止めます。記録は初期状態では無効です。

保存先は固定で、`%USERPROFILE%\.wt.debug\ocr-traces` です。ファイル名は `ocr-*.jsonl` で、開始時に実際のパスをログに出します。記録内容は以下の通りです。画像そのものは保存しません。ファイルは記録中も読み取り可能です。

JSON Lines の先頭行は形式バージョン 1 のヘッダーです。2 行目以降はすべて同じ形式で、1 行が 1 OCR フレームです。各フレームには記録開始からの相対時刻（`RelativeTimeTicks`）、対象画像の幅と高さ、および `IOcrModule.RecognizeAsync` が返した統合済み `TextRect` の OCR 文字列、X、Y、Width、Height、FontSize、Angle、MultiLine を保存します。画像サイズは毎フレーム保存するため、対象ウィンドウのサイズ変更も記録できます。フレーム番号、画像、翻訳結果、色は保存しません。

別ワーカーが `PeriodicTimer` の周期ごとに、その間のフレームをまとめて追記します。書き込みに失敗した分は保持して再試行し、失敗はログに記録します。記録の失敗によって OCR・翻訳処理は停止しません。

## テストでの再入力

本体に再生機能はありません。`WindowTranslator.Tests/OcrTraceTests.cs` に、ヘッダーとフレームを読み、保存順に `OcrTextTracker` へ入力する例があります。形式バージョンが未対応なら読み込みを拒否し、未知の追加フィールドは無視します。

レコーダーは各フレームを受け取った時点で相対時刻を採取します。テストでは `RelativeTimeTicks` を時刻として与え、記録されたフレーム順序・画像サイズ・時間間隔で追跡処理を実行できます。比較するアルゴリズムには同じトレースと追跡設定を使用してください。

保存された列から位置・サイズの変動、文字列の変更、欠落と復帰、実時間の反映遅延を集計できます。トラック ID や分割・統合の内部状態はトレースに含まれません。追跡処理時間はテスト側で各入力の処理を計測できます。

## 共有前の確認

不具合報告に添付する前に、JSON Lines の全文を開いて OCR 文字列を確認してください。機密情報があれば共有用のコピーから削除または置換してください。
